How-to guide: for a project manager who has just heard the owner state a rule, preference or decision.

# How to record an owner's rule

This guide shows you how to capture a rule so the owner never has to
repeat it.

1. Stop before acting on the message.
2. Copy the owner's exact words. Don't paraphrase.
3. Search the rules record for an entry on the same subject.
   - If one exists and the new words change it, add a new entry and mark
     the old one `superseded by R-<new>`.
   - If one exists and agrees, add nothing.
4. Add the entry in the [record format](../reference/skills/standing-rules.md):
   id, title, quote, date, where it was said, scope, what it applies to.
5. If the message was a correction ("don't only do X, also do Y"),
   record it as a rule about how the work is done.
6. Tell the agents whose open packages it affects, in one line with the
   entry id, and update those packages' done-when.
7. If the rule conflicts with another live rule or would defeat the
   owner's goal, tell the owner once with the conflict and a proposed
   wording. Until they answer, the newer rule stands.

Don't add rules the owner did not state or agree to.
